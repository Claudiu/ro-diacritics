# Architecture

## Summary

Two halves joined by one file format. Python (`uv`, PyTorch) turns Romanian Wikipedia
into a trained character-level transformer and exports `config.json` +
`model.safetensors`. Rust (candle) loads that export and restores diacritics, as a native
CLI and as a WASM module for a static demo page. Training is one command after `git pull`.

## Problem framing

- One label per character of diacritic-free input: `none`, `breve_comma` (ă ș ț),
  `circumflex` (â î). The base letter in the input selects the actual diacritic, so three
  classes cover five letters and no î/â position rule is needed at decode time.
- Only `a i s t` (any case) can carry a diacritic. Loss and metrics are computed on those
  "candidate" positions only; accuracy over all characters would be dominated by letters
  that can never change.
- Text is processed in 256-character windows with 32 characters of overlap; each position
  is owned by the window where it sits furthest from an edge.
- Decoding applies a prediction only when its confidence ≥ `threshold` (tuned on
  validation for precision).

## Ports

| Port | Methods | Adapter now | Swap target | Fake |
|---|---|---|---|---|
| `CorpusSource` (Py) | `iter_documents()` | `WikipediaSource` (HF parquet, streamed) | `LocalFilesSource`, OSCAR | `InMemorySource` |
| `ArtifactStore` (Py) | `write(name, bytes)`, `read(name)` | `LocalDirStore` | S3 / HF Hub | `InMemoryStore` |
| `Restorer` (Rust) | `restore(&str)` | `Transformer` (candle) | ONNX, BERT-class | `Identity` |

Export contract: `config.json` (format version, dims, alphabet, labels, overlap,
threshold) + `model.safetensors` with PyTorch parameter names. `crates/domain/src/config.rs`
validates it; `FORMAT_VERSION` is bumped on any change.

## Mirrored domain

`normalize`, `decode`, `windows` and the alphabet exist in both `src/diacritics/domain/`
and `crates/domain/`. That is the one deliberate duplication: training labels and
inference must agree exactly, and the two sides run in different languages.
`test/fixtures/*.jsonl` are loaded by both test suites, and `test/fixtures/parity/` (a
tiny random-weight export plus PyTorch outputs, regenerated by `scripts/parity.sh`)
checks the candle forward pass against PyTorch to 1e-4.

## Layout

```
src/diacritics/
├── __main__.py        CLI + wiring (names WikipediaSource and LocalDirStore)
├── config/settings.py typed settings from DIACRITICS_* env, validated
├── common/            env, JSON logging, atomic download
├── domain/            label, normalize, decode, alphabet, windows, example
├── corpus/            source port, wikipedia, local_files, memory, filter
├── artifacts/         store port, local_dir, memory
├── dataset/           shards (uint8 windows on disk, memmapped), build
├── model/             encoder (explicit pre-LN transformer), infer (windowed Predictor)
├── baseline/          most-frequent-form-per-word
├── metrics/           precision/recall per class on candidates, word accuracy
├── train/             resumable loop, exports best by candidate accuracy
└── export/            safetensors + config.json
crates/
├── domain/            no driver deps: alphabet, label, normalize, decode, windows, config, Restorer
├── model/             candle Transformer, parity test, criterion bench
├── cli/               `diacritics restore`
└── wasm/              `new Diacritics(config, weights).restore(text)`
web/                   index.html + worker.js (model runs in a Web Worker)
scripts/               train.sh, build-wasm.sh, serve-web.sh, parity.sh, benchmark.sh, check.sh
test/fixtures/         shared cases + parity export
```

## Budget

| Item | Target | Measured (skeleton, 4-core laptop) |
|---|---|---|
| Model | ≈10.8M parameters (6 layers, d=384, 6 heads, ff=1536, window 256) | 43 MB fp32 export (≈0.4 s per paragraph in WASM); fp16 would halve it |
| WASM binary | ≤ 1.5 MB gzipped, single thread + SIMD, no COOP/COEP needed | 1.04 MB raw, 0.29 MB gzipped |
| Native latency | — | 8.9 ms per 73-char sentence, 104 ms per 876-char paragraph (≈8.3K chars/s, `scripts/benchmark.sh`) |
| Browser latency | ≤ 5 ms per sentence while typing | not yet measured with the real model; expect 2–4× native |
| Input cap | 20 000 characters per `restore` call (`MAX_CHARS`) | enforced in `crates/model` |
| Data pipeline | streamed, RSS ≤ 2 GiB | raw 272+195 MB parquet, shards ≈1 GB, under `data/` (gitignored) |
| Training | bf16 on CUDA, batch 256 × 256 chars, checkpoint every 1000 steps | smoke-tested on CPU end to end |

Padding is masked out of attention, so cost is proportional to the text length, not the
window. If the browser number misses its target once the model is trained, the levers are,
in order: a smaller config (`D_MODEL=128`, `N_LAYERS=3` cut compute ≈3×), re-running only
the windows that changed while typing, fp16/int8 weights.

## Growth path

1. Demo on a laptop: `scripts/serve-web.sh`. GitHub Pages or Caddy on a VPS later: the
   same static files, deploy only.
2. Server-side API: a `crates/http` on the `Restorer` trait; no model changes.
3. Better model (BERT-class): a second `Restorer` adapter behind the same export
   contract or its own; CLI, WASM and page stay as they are.
4. More data: another `CorpusSource` adapter (OSCAR, news) wired in `__main__.py`.

## Milestones

1. Skeleton (this): both domains green on shared fixtures, parity test, CLI, wasm build,
   demo page, CI. `feat(repo): Initial skeleton`
2. Baseline numbers on the full corpus. `feat(baseline): Most frequent form per word`
3. Full training on the 5090, export, eval, threshold tuned. `feat(train): First model`
4. Demo with the real model; size/int8 tuning if needed. `feat(web): Browser demo`
